# Historique des versions

Règle : la version la plus récente est toujours à la racine du dossier. Avant chaque évolution,
l'état précédent est copié dans `versions/` (un dossier par version). Pour revenir en arrière ou
comparer, ouvre le dossier de la version voulue. (Au Module 6, Git prendra le relais.)

## v1.4 — Mode « en ligne » : l'éditeur dans l'application web de l'organisation (12/10/2026)
Demande de Brice (12/10, incrément 2 de l'application web) : reprendre l'application d'origine telle quelle, avec un enregistrement dans l'espace de l'organisation.
- **Deux modes, un seul code** (`js/en-ligne.js`) : en local (fichier ouvert sur le poste), rien ne change. En ligne (`<html data-mode="en-ligne">`, posé par la copie de l'éditeur dans l'application web), le document (`?doc=…`) et la cartographie viennent du serveur, et **rien n'est gardé dans le navigateur** (`store.js`, `cartographie-store.js`).
- **Ouverture depuis le serveur** : `store.demarrerAvec()` et `cartographie-store.demarrerAvec()` — même nettoyage qu'un fichier .json, historique d'annulation remis à zéro ; un contenu illisible n'est pas ouvert.
- **Enregistrement automatique** (`js/synchro.js`, testable sans navigateur) : 1,5 s après la dernière modification, une requête à la fois, nouvel essai automatique en cas de coupure ; numéro de version : si quelqu'un a enregistré entre-temps, une fenêtre propose **recharger** ou **garder ma version**. Session expirée, document supprimé, droits retirés, document trop gros : enregistrement suspendu et expliqué, le travail reste dans la page et peut être **téléchargé en .json**.
- **Lecture seule** selon le rôle (`store.verrouiller()`, `cartographie-store.verrouiller()`) : toute modification est défaite, les champs ne se modifient pas, la cartographie n'affiche plus ses boutons de modification ; aperçus, synthèse, Word et PDF restent disponibles.
- **Interface en ligne** (`js/en-ligne-ui.js`) : écran d'ouverture, état « Enregistré / Enregistrement… » dans l'en-tête et dans la fenêtre de cartographie, lien **« ← Mes documents »** (enregistre avant de partir), menu Fichier sans « Nouveau document » (les documents se créent depuis la liste) mais avec « Télécharger une copie (.json) » ; « Créer l'instruction de travail » crée un **nouveau document** de l'organisation (la procédure reste intacte) ; cartographie seule (`?vue=cartographie`).
- **Vérifié** : 466 tests Node au vert (dont `tests/synchro.test.mjs` et `tests/en-ligne.test.mjs`, 21 nouveaux) ; parcours complet dans Chromium contre l'application web (création, saisie, rechargement, exemple, Word, import Word, cartographie par modèle et par PDF, instruction N3, conflit, session expirée, lecture seule, suppression, étanchéité entre organisations).

- **Parcours en 4 étapes** : chaque étape ne s'ouvre que lorsque la précédente est remplie ; sous les champs, la liste de ce qu'il reste à renseigner.
  1. *Identification* : organisation / société, direction / site (facultatif), processus de rattachement, pilote du processus, intitulé de la procédure, code envisagé, version, type de document (procédure, instruction, les deux). Repris de la fiche de collecte.
  2. *Déroulé* : rôles, événement déclencheur, instructions, fin.
  3. *Synthèse* : relecture de tout (identification, déroulé, risques, niveau 3), conformité au langage, longueur, points d'attention ; l'éditeur des 13 sections est ici ; case « Je valide cette synthèse ». Toute modification après validation rend la validation caduque.
  4. *Génération* : Word (.docx) et PDF.
- **Risques dans chaque instruction** : case « Cette instruction permet de maîtriser un risque » → risque, causes, gravité (1-4), probabilité (1-4), mesure de maîtrise (5 risques au plus). Criticité = gravité × probabilité (seuils de la fiche : 1-3 acceptable, 4-8 à surveiller, 9-16 inacceptable). La section 10 est **générée** à partir de ces saisies (un tableau par défaut, comme les sections 5 et 6).
- **Niveau 3 dans chaque instruction** : case « fait l'objet d'une instruction de travail », avec son code (obligatoire) et son intitulé. Dans le logigramme, l'instruction porte un libellé souligné et la ligne « N3 : code » ; le code apparaît aussi dans la colonne Support du tableau de la section 6.
- **Word (.docx)** fabriqué par l'application (sans bibliothèque) : cartouche d'identification, sommaire, 13 sections, tableaux, logigramme en image sur une page A4 entière, pied de page « code – version … Page X sur Y ». Vérifié : XML valide, ouverture sous LibreOffice, 7 pages pour PR-XXX-01.
- **PDF** : le bouton ouvre l'impression du navigateur, qui n'imprime que le document (choisir « Enregistrer au format PDF »).
- **Estimation de pages** recalculée en points (police, marges et tableaux du vrai document) : PR-XXX-01 = 7 pages estimées, 7 mesurées sous Word/LibreOffice (avant : 9 estimées pour 7 réelles).
- **Import Word** : reprend aussi l'identification du cartouche (organisation, direction / site, processus, pilote), lit le Word produit par l'application (sommaire ignoré, titre en style « Titre »).
- **L'exemple PR-XXX-01** contient maintenant son identification et les 6 risques de sa section 10.
- Corrections : le brouillon n'était plus repris au rechargement (ordre d'initialisation, défaut déjà corrigé en v0.7 puis réintroduit ; un test le protège) ; le mot « null » s'affichait à l'étape Génération ; affichage sur écran étroit (aucun défilement horizontal).
- Limites connues : le type « instruction (niveau 3) » ou « les deux » choisit et repère les instructions de niveau 3 mais ne génère pas encore leur document ; le sommaire Word est statique (sans numéros de page) ; l'import ne relit pas encore le tableau des risques de la section 10 dans les instructions.
- 82 tests (36 nouveaux).
